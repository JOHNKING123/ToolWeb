使用说明

解码：文件经 FileReader 读入 ArrayBuffer 后，用 Web Audio API 的 decodeAudioData 在浏览器本地解码为 AudioBuffer（MP3/WAV/OGG/M4A 是否支持取决于浏览器解码器；Safari 对 OGG 支持有限）。可一次选择多个文件，也可分多次添加。
排序：列表序号即拼接顺序，▲/▼ 调整，✕ 删除；排序或删除后合并结果自动重新生成，导出内容与列表顺序严格对应。
归一化：各段统一重采样到 44100Hz（与 MP3 编码路径一致，保证段间衔接无采样率跳变）；声道统一为全单声道→单声道、否则立体声（单声道段复制为双声道，多声道取前两声道）。
淡入淡出 / 静音间隔：可选每段开头淡入、结尾淡出（余弦曲线，默认 0ms），或在相邻段之间插入自定义秒数的静音；两者都计入总时长。
试听：把拼接后的完整音频一次播放，进度实时显示。
导出：WAV 为手工编码的 16-bit PCM（44 字节标准头）；MP3 经本地 lamejs 编码（64/128/192/320kbps 可选，长音频分块编码不卡死页面）。
隐私：全程无网络请求 —— 上传、解码、排序、拼接、试听、编码、下载都在你的浏览器里完成，可在 DevTools Network 面板验证。

quiz 常见问题

合并音频会被上传到服务器吗？
不会。所有步骤（上传读取、解码、排序、归一化、拼接、试听、WAV/MP3 编码、下载）都在你的浏览器本地完成，脚本内零 fetch/XHR。你可以在开发者工具的 Network 面板验证：添加音频后没有任何网络请求发出。
不同采样率/声道的音频能合并吗？
可以。合并前所有片段会自动归一化：统一重采样到 44100Hz，声道统一为全单声道→单声道、否则立体声（单声道片段复制为双声道）。归一化后拼接，衔接处不会出现采样率跳变或声道错乱。
合并后总时长是多少？
默认（无淡化、无静音间隔）时，总时长 = 各段时长之和（±0.1s 内，取决于重采样舍入）。设置了静音间隔后，每段之间会计入相应秒数；淡入淡出不改变总时长。
MP3 比特率越高文件越大吗？
是的。64/128/192/320kbps 四档，比特率越高音质越好、文件越大。预估体积 ≈ 比特率 × 总时长 ÷ 8（页面会显示各格式的预计导出体积）。
支持哪些格式？一次能加多少个文件？
支持 MP3 / WAV / OGG / M4A 等常见格式（实际以浏览器解码能力为准）。文件数量没有硬性上限，但解码后的音频全部驻留内存 —— 超长音频（如数小时）请注意浏览器内存占用。
导出的文件叫什么名字？
自动命名为「首个片段的文件名（去扩展名）_merged.扩展名」，例如 会议记录_merged.mp3。如需其他名字，下载后重命名即可。
