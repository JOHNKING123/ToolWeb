help_outline 使用说明

怎么粘：在浏览器开发者工具 Network 面板点一条请求、复制响应头，或用 curl -i 拿到响应头，整段粘贴进来；含状态行 HTTP/1.1 200 OK 的整段也能直接粘，状态行会单独识别、不当作头。
解析规则：头名大小写不敏感，统一归一化为规范大小写（如 content-type → Content-Type）；以空格或制表符开头的行是折行续行，会并入上一头的值；多个 Set-Cookie 分别列出、不合并丢弃；没有冒号的行会报错并指明行号；值为空的头照常列出并标注「值为空」；空行自动忽略。
分类：每条头归入安全、缓存、内容、其他四类之一，便于排障时按关注面扫读。
复制报告：点「复制解析报告」得到纯文本报告：状态行、逐项「头名: 值 —— 中文释义」、六项安全头判定汇总与「缺失 N 项」；复制失败时会提示手动复制指引。
隐私：全部解析在浏览器本地完成，不发起网络请求，不上传粘贴内容。

quiz 常见问题

能直接输入网址让工具去抓响应头吗？
不能。本工具只解析用户粘贴的文本、不主动抓取任何 URL——远程抓取需要后端与跨域支持，不属本工具；要抓包请用浏览器开发者工具或 curl -i 网址，再把结果粘贴进来。
安全头判定 Missing 是不是代表网站不安全？
不是。本工具不做安全评分、不承诺合规结论：Missing 只表示「未在粘贴文本中出现」这一项，是否合规要结合你的安全基线、部署架构（如 CDN 是否剥离头）综合判断。
这里的中文释义权威吗？
中文释义仅供参考，规范语义以 RFC/MDN 为准。释义为自有改写、便于快速理解，遇到语义争议请查阅 RFC 规范文档或 MDN 英文原文。
为什么有的头没有中文释义？
非标准／自定义头（尤其是 X- 开头的自定义头）只原样列出、不给标准释义；较少见的标准头若未收录，也会原样列出并提示以 RFC/MDN 为准。
重复的 Set-Cookie 为什么不合并？
因为每条 Set-Cookie 都是独立的一条指令，合并会丢信息、改语义；本工具按原样分别列出，复制报告里也是逐条出现。
这个页面会联网或上传数据吗？
不会。解析、释义、判定、报告生成全部在浏览器本地完成，JS 不含 fetch/XHR 调用，你可以在开发者工具 Network 面板验证。
