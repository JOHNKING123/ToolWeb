真限制（请先看清再用）：

1. 仅覆盖常用旗标子集：--name、-p/--publish、-v/--volume、-e/--env、--restart、--network/--net、-i/-t、--entrypoint、-w/--workdir、--user、--hostname、--expose、--label 单值；--privileged、--cap-add、--device、--dns、--add-host、--health-*、--link 等一律进「不支持」诊断列表，不静默丢弃、不编造 compose 字段。

2. -d / --rm 在 compose 里没有等价字段：compose 默认即后台语义（docker compose up -d），解析时记为「已忽略」而非报错。

3. 输出不含 version 字段：现代 Compose 已废弃 version，写它反而会误导。

4. 环境变量值含 $ 时已转义为 $$：compose 会把 $ 当作变量插值，不转义会把你的值替换掉；诊断列表里会逐项提示，请确认这就是你想要的。

5. 端口 / 挂载 / 环境变量值一律加引号输出，避免 8080:80、含 : 或 # 的值被 YAML 误读。

menu_book 使用说明

  1. 粘贴 docker run 命令（支持多行 \ 续行、单双引号、组合短旗标），解析表会逐项列出服务名、镜像、容器名、端口、挂载、环境变量、重启策略、网络与启动命令。
  2. 先看诊断列表：不支持的旗标逐项列出（请在 compose 中手动对应），已忽略的旗标（-d / --rm）与 $ 转 $$ 提示也逐项列出，没有一项是静默丢弃的。
  3. 服务名优先取 --name，否则取镜像去掉仓库前缀与 :tag / @digest 后的 basename 并清洗（小写、非法字符转 -）；--name 原值保留为 container_name，两者在解析表中对照展示。
  4. 确认无误后点「复制 YAML」或「下载 docker-compose.yml」，保存后按需改写再 docker compose up。
  5. 点示例一键载入 4 组典型命令（请按需改写），载入后仍可编辑再转换；点「重置回初始输入」回到本次的初始命令。

quiz 常见问题

为什么 --privileged 没进 YAML？
因为它不在本工具承诺的常用旗标子集内。直接编造一个 compose 字段很容易编错语义，所以它进了「不支持」诊断列表并逐项列出，你可以在 compose 中按官方文档手动对应 privileged: true，而不是拿到一份看似完整实则不对的配置。
-d 和 --rm 为什么被忽略了？
compose 默认即后台语义（docker compose up -d），不需要 detach 字段；--rm 在 compose 里也没有等价字段，容器随服务启停管理。所以两者记为「已忽略」而不是报错，更不是静默丢弃。
环境变量里的 $ 为什么变成了 $$？
compose 会把 $ 当作变量插值：写 PRICE=$5 会被解析成变量引用，值就变了。转成 $$ 后 compose 才会原样输出 $，诊断列表里会逐项提示，请确认这就是你想要的。
输出里为什么没有 version 字段？
现代 Compose 已废弃 version 字段，写它没有意义还可能误导旧教程读者，所以输出从 services: 直接开始。
服务名是怎么推出来的？
优先取 --name；没有 --name 时取镜像名去掉仓库前缀与 :tag / @digest 后的 basename，再做小写与非法字符转 - 的清洗；--name 原值保留为 container_name，解析表里两者对照展示。
我的命令会被上传或验证吗？
不会。全部转换在浏览器本地完成，零网络请求；不连 Docker、不验证镜像是否存在、不验证端口是否被占用，生成的只是文本配置。
