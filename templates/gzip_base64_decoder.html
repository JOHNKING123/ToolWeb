Gzip Base64 解码器

粘贴 gzip 压缩后的 Base64 文本 → 归一化 → 解码 → 校验 gzip 魔数 → 原生解压 → 输出 UTF-8 原文。接口调试里常见的「裸解码只得乱码」问题，一贴即解。

隐私声明：内容不出浏览器。归一化、解码、解压与反向压缩全部在当前页面本地完成，不上传到任何服务器，不做任何存储与记录。本页面无后端调用、无外部请求。

输入：gzip 压缩后的 Base64

归一化会自动做：去空白（含换行）→ 剥离 data:*;base64, 前缀 → url-safe - _ 转回 + / → 按需补 = 至 4 的倍数。非法字符会按位置报错，不静默丢弃。

输出：解压后原文

反向演示：文本 → gzip → Base64

用浏览器原生 CompressionStream('gzip') 把文本压成 gzip 再转标准 Base64，可点「填入上方解码」验证往返。

真限制（请先了解）

  • 仅 gzip 格式：zlib、deflate、brotli、xz 等不在范围；魔数不是 0x1F 0x8B 的输入会明确报错。
  • 仅 UTF-8 文本输出：解压后非有效 UTF-8（如二进制文件）不强行展示乱码，会报错并给出解压后字节数。
  • 老浏览器明示不支持：没有 DecompressionStream('gzip') / CompressionStream('gzip') 的浏览器会直接提示不支持，不静默失败。
  • 容量上限 10MB：gzip 字节或解压后文本字节超过 10MB 时拒绝处理，不静默截断。
  • 不上传、不收集：所有处理只在浏览器本地完成。

使用说明

  1. 在输入区粘贴 gzip 压缩后的 Base64 文本（日志里带换行、带 data: 前缀、url-safe 形式均可）。
  2. 点「解码并解压」，下方输出区显示 UTF-8 原文，并给出 Base64 字符数、gzip 字节数与原文字节数。
  3. 点「复制原文」或「下载 gzip-decoded.txt」取用结果。
  4. 不确定手头的 Base64 是不是 gzip？点「载入示例」载入固定向量 H4sIAAAAAAAAA/NIzcnJ11EIyc/PCU9NUuQCAInvfO4QAAAA，解出 Hello, ToolWeb! 即说明流程正常。
  5. 反向演示区可把任意文本压成 gzip Base64，再填回上方验证往返。

常见问题

裸 Base64 解码出来是乱码，怎么办？
乱码往往说明原文先被 gzip 压过、再转 Base64：裸解码只能得到 gzip 二进制。本工具在解码后继续 gunzip，正好补上这一段。
报错「不是 gzip 数据」是什么意思？
解码后前两字节不是 gzip 魔数 0x1F 0x8B。请先用 Base64 编码／解码工具确认输入是不是裸 Base64，或确认压缩格式确实是 gzip（不是 zlib / deflate / brotli）。
报错「gzip 数据损坏或不完整」怎么办？
输入可能被截断、复制缺字符或混入了额外内容。请核对来源的完整 Base64，非法字符位置会在归一化阶段先报出来。
解压后是二进制文件怎么办？
本工具只输出 UTF-8 文本；二进制内容会报「不是有效的 UTF-8 文本」并给出字节数，不强行展示乱码。
内容会上传到服务器吗？
不会。解码与解压全部用浏览器原生能力在本地完成，本页面不发起任何网络请求。
老浏览器打不开怎么办？
需要支持 DecompressionStream('gzip') 的新版 Chrome / Edge / Firefox / Safari；不支持时页面会明示，不会静默失败。
