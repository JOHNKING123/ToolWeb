help_outline 使用说明

什么是 NAT 类型检测？
路由器/运营商的 NAT 会把内网地址映射为公网地址。P2P 联机（如联机游戏、远程桌面直连）需要「打洞」穿透 NAT，不同 NAT 类型的打洞难度差异很大。本工具向两台 STUN 服务器分别查询你的公网映射地址，对比映射行为推断 NAT 类型。
怎么判断锥形 NAT 还是对称型 NAT？
向两台不同 STUN 服务器查询：如果两次返回的公网 IP＋端口完全一致，说明映射与目标端点无关 → 锥形 NAT（Cone NAT）；如果 IP 或端口不一致，说明映射随目标变化 → 对称型 NAT（Symmetric NAT）特征。这是浏览器可行的启发式近似，不是 RFC 5780 的完整行为测试。
浏览器有什么做不到的？（硬限制）
浏览器只能看到映射行为，无法区分 Full Cone / Restricted Cone / Port Restricted Cone 三种过滤行为（它们映射行为相同、过滤策略不同），所以锥形 NAT 结果只给到「锥形」一层，不会细化三类过滤类型。
对称型 NAT 该怎么办？
P2P 打洞成功率低，建议改用 TURN 中继服务器转发流量，或换到锥形 NAT 网络（如手机热点）再试。锥形 NAT 通常可以直接尝试 UDP 打洞。
检测失败「未收到 srflx」怎么办？
最常见原因是 UDP 出向被拦截（公司/校园网防火墙）。排查：① 换手机热点再测；② 检查浏览器未禁用 WebRTC；③ 公司网络咨询 IT 是否放行 UDP 3478/19302 端口；④ 尝试自定义其他 STUN 服务器（如 stun:stun.cloudflare.com:3478）。
同一网络重复检测结果会一致吗？
映射行为通常是稳定的，同一网络重复检测判定应一致。如果两次结果不同，说明网络环境有变化（如运营商会话超时后重新分配映射），可多测两次取多数结论。
我的公网 IP 会被记录吗？
本工具不记录、不上传任何数据。你的公网 IP 只会被你选择的 STUN 服务器看到（STUN 协议本身需要），页面上显示的 IP 仅存在于你的浏览器内存中。
