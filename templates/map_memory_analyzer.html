使用说明

  1. 用 arm-none-eabi-gcc … -Wl,-Map=firmware.map 生成 map 文件（或 STM32CubeIDE／PlatformIO 的链接选项里开启），把内容粘贴到输入区，或点「读取本地文件」直接读 .map（FileReader 本地读取，零上传）。
  2. 点「解析内存占用」：总览卡显示各内存区域（FLASH／RAM）的使用条、百分比、已用／剩余字节；段汇总表、对象文件 Top20 均可点击表头排序；每段可展开看输入节明细（含 *fill* 填充行标识）。
  3. 「复制中文占用报告」或「下载报告 .txt」可把分析结果带走贴进评审文档。
  4. 点「载入示例」可先看一个固定示例 map 的解析效果，再粘贴自己的文件。

常见问题

为什么只支持 GCC ld -Map？
ARMCC（armcc/armlink）与 IAR 的 map 结构与 GNU ld 完全不同（IAR 为模块汇总表风格），首版只做 GCC ld -Map 一套，保证解析质量；非 GCC 文件会明确报格式错误。ARMCC／IAR 支持记在 roadmap，不承诺日期。
能看到每个函数／变量各占多少字节吗？
不能。ld map 默认只列到输入节粒度（如 .text.main 级），没有单符号大小；要符号级统计请用 nm --print-size 或 size。这是真限制，不是 bug。
为什么 .data 在 Flash 和 RAM 里都占了？
这是口径说明，不是重复计算：.data 的初始值以镜像形式存放在 Flash（load address），运行时搬到 RAM。因此 Flash 占用含 .data 初始化镜像，RAM 占用含其运行地址，两边各计一次。
我的 map 会被上传吗？
不会。全部解析在浏览器本地完成，本页面零网络请求；「读取本地文件」用 FileReader 只读进内存，不上传。
