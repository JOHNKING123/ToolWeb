help_outline 使用说明

这 12 条规则都检查什么？
五组：图片与替代文本（图片 alt，空 alt 装饰图合法不误报）、表单与交互控件（表单 label、按钮可访问名、链接文本）、标题与文档结构（标题层级、html lang、页面标题）、键盘与 ARIA（tabindex、重复 id、ARIA 引用完整性）、媒体与对比度（视频字幕/音频文字稿、文字对比度）。全部是确定性规则，无 AI、无猜测。
分数是怎么算的？
每条规则：通过 100 分、警告 50 分、失败 0 分，总分 = 12 项均值四舍五入。等级：优秀 ≥85、良好 ≥60、待改进 <60。警告不致命但值得优化，失败项建议上线前修掉。
为什么说这是「自查工具」，不是 WCAG 合规认证？
真正的无障碍合规需要真人键盘操作测试、屏幕阅读器实测、动态交互验证，这些纯前端静态规则都做不到。本工具帮你低成本发现「低级硬伤」（缺 alt、无 label、跳级标题等），但高分不等于通过 WCAG 认证，上线前重要页面仍建议用 axe / Lighthouse 或人工复核。
空 alt 的图片会被判失败吗？
不会。alt="" 是装饰图的合法写法，工具会识别为装饰图并通过（文案里会注明）。只有完全缺少 alt 属性的内容图片，或图片链接（a 包裹 img）的 alt 为空，才会判失败——后者会让整个链接失去可访问名。
表单 label 有哪几种合法写法？
三种都认：① 显式关联 <label for="控件id">；② label 直接包裹控件；③ aria-label / aria-labelledby。注意 placeholder 不能替代 label。三种都不满足才判失败，不会误报。
对比度是怎么判的？为什么有时候只给警告？
只对内联样式里前景色＋背景色都明确的文字计算对比度（正文要求 ≥4.5:1，大字 ≥3:1）。背景是图片、渐变、半透明或写在外部 CSS 里的，工具看不到真实渲染效果，只能给「手动核对」警告——这是保守设计，避免误判。
为什么粘贴源码，而不是输入网址？
浏览器跨域限制下，前端无法直接抓取任意网址的源码。粘贴源码的方式零后端、零等待，而且源码不出浏览器，未上线的页面也能放心检查。
我的 HTML 会被上传吗？
不会。解析（DOMParser）与打分全在本地完成，页面脚本不发起任何网络请求（零 fetch / XMLHttpRequest）。你可以断网后使用验证。
报告里的修复建议可以直接照着改吗？
可以。每条失败/警告都附了中文修复建议（含 WCAG 2.2 条款号与示例代码），按建议修改后重新粘贴检查，看分数变化即是最直接的验证。
