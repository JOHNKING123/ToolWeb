五条真限制

                

                    
1. 只解析 CREATE TABLE：CREATE INDEX、ALTER TABLE、INSERT 等语句不解析，会进入「未解析诊断」列表；SET / USE 这类转储样板语句直接跳过、不计入诊断。

                    
2. 复杂 DDL 可能解析失败：存储过程、触发器、视图、分区表、CHECK 表达式、GENERATED 计算列等只做宽容跳过或进诊断，不展开语义；CREATE TABLE ... AS SELECT / LIKE 口径暂不支持。

                    
3. 关系只按外键推断：外键所在表画为多端、被引用表画为一端；无外键的表之间不猜关系，命名相似（如 user_id）但没有外键声明的字段不会自动连线。

                    
4. Mermaid 标识符限制：erDiagram 的实体名与属性名须为英文标识符，中文或特殊字符会被转写为下划线形式（如 用户 → __），原始名称保留在字段表里；转写后重名的属性会自动加 _2 后缀区分。

                    
5. 输入上限 20000 字符：超大 DDL 请先按库拆分再粘贴；渲染依赖本地 Mermaid 10.9.3，表特别多时关系图可能渲染缓慢，建议一次不超过 30 张表。

                

            


            

                
常见问题

                

                    
支持哪些数据库的 DDL？

                    
MySQL、PostgreSQL、SQLite 三种方言宽容解析：反引号、双引号、方括号三种标识符，字段级与表级主键／外键、REFERENCES、CONSTRAINT FOREIGN KEY、ON DELETE / ON UPDATE 均支持；--、#、/* */ 三种注释会先剥离。

                    
没有外键的 DDL 能画图吗？

                    
能。没有外键时每张表单独成块、关系清单为空；关系只按外键推断，不会按字段名相似度猜测连线。

                    
「未解析诊断」里出现内容怎么办？

                    
那是解析器明确识别不了的行（例如 CREATE INDEX 或写法特殊的字段定义），已原样列出、未做任何推测；不影响已解析部分的出图，可把该行删掉或改写成标准 CREATE TABLE 写法后重新解析。

                    
我的 DDL 会被上传吗？

                    
不会。解析、生成 Mermaid 代码、渲染与导出全部在本地完成，不发起后端请求；渲染引擎 Mermaid.js 10.9.3 是随页面加载的本地静态文件，你可以在 DevTools 的 Network 面板验证（除加载本页面资源外无其他请求）。
