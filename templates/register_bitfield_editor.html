🔧 寄存器位域查看与编辑器

32 位寄存器值输入（hex/dec/bin）→ 32 位位图点击置位/清零 → 实时输出 HEX/DEC/BIN 与 C 宏定义

寄存器值输入 （三种格式，输入后即时解析）

自动识别：0x/0X 开头为十六进制，0b/0B 开头为二进制，含 a–f 为裸十六进制，其余按十进制解析；范围 0–4294967295（32 位）。

32 位位图 （bit31 … bit0 左到右降序，每 4 位一组，点击切换置位/清零）

实时输出

HEX（0x 前缀，8 位大写）
DEC（无符号十进制）
置位位列表（升序）
BIN（32 位，4 位分组）

C 宏定义 （置位位宏降序排列，掩码自动取反）

只允许字母、数字、下划线，字母或下划线开头

使用说明

  1. 在输入框填 32 位寄存器值：0xDEADBEEF（hex）、3735928559（dec）或 0b101（bin），输入即时解析并刷新位图。
  2. 点击位图中的任意位格，即可切换该位的置位/清零；置位位以蓝色高亮显示。
  3. HEX / DEC / BIN / 置位位列表随操作实时更新，宏定义区同步输出 C 宏。
  4. 宏前缀默认 REG，可改（如 GPIOA→#define GPIOA_BITn），复制或下载 register-bitfield.h / register-bitfield.txt 即可带走代码。
  5. 点「载入示例」可一键演示全流程：输入 0xDEADBEEF → 位图点亮 → 切换任意位 → 复制/下载宏。

常见问题

REG_SET_MASK 和 REG_CLR_MASK 各是什么？
SET_MASK = 当前值本身（置位用：REG |= REG_SET_MASK）；CLR_MASK = 当前值按 32 位取反（清零用：REG &= REG_CLR_MASK）。先用宏算好掩码，代码里只做位运算，避免手算掩码写错。
宏里的 (1u << n) 为什么用 1u？
u 后缀表示无符号，避免有符号移位到 bit31 时的未定义行为与符号扩展。bit31 的宏写作 (1u << 31)，符合 C 语言位操作惯例。
裸 hex 和十进制怎么区分？
自动识别口径：含 0x 前缀或含 a–f 字母的一律按十六进制，其余按十进制。DEADBEEF（裸 hex）与 3735928559（十进制）都能正确识别；需要强制口径时用格式下拉框手动选择。
能做 8/16/64 位寄存器吗？
不能。本工具只做 32 位寄存器位级可视化编辑与宏生成（见真限制说明）。
我的输入会被上传吗？
不会。全部计算在浏览器本地完成，本页面零网络请求，寄存器值不出本机。
