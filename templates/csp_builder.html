help_outline 使用说明

三步生成：① 勾选要用的指令（不勾 default-src 时建议至少勾它作兜底）；② 点快捷关键字（如 'self'、'unsafe-inline'）或在输入框里填自定义源（多个源用空格、逗号或换行分隔，如 https://cdn.example.com）；③ 需要先观察效果就打开 Report-Only 测试模式，再点复制。
源的写法：关键字必须带单引号（'self'、'none'、'unsafe-inline'）；域名写完整 scheme（https://cdn.example.com）；data:、blob:、https: 这类 scheme 源直接填。

quiz 常见问题

生成的头直接配到 Nginx / Apache 就能生效吗？
能。复制「响应头全文」，Nginx 用 add_header Content-Security-Policy "...";，Apache 用 Header set Content-Security-Policy "..."；怕配错先开 Report-Only 模式观察上报，确认无误再切正式头。
为什么 <meta> 片段里有些指令不生效？
这是规范限制：<meta http-equiv> 不支持 frame-ancestors、report-uri、sandbox 等部分指令，它们必须通过 HTTP 响应头下发——这也是本工具同时输出两种形式的原因。
report-uri 和 report-to 该用哪个？
report-uri 写上报地址即可，简单直接，但已趋向废弃；report-to 是新口径，需要额外配置 Report-To / Reporting-Endpoints 响应头声明端点。新项目建议优先 report-to。
'unsafe-inline' 是不是不安全？
是的。它会放行页面内所有内联脚本和样式，基本抵消了 CSP 对 XSS 的防护价值；能改代码就优先用 nonce 或 hash，实在改不动再用它过渡。
这个页面会联网或上传数据吗？
不会。指令拼装、预设、复制全部在浏览器本地完成，JS 不含网络请求调用，你可以在开发者工具 Network 面板验证。
