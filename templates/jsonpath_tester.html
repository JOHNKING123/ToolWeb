支持的表达式子集

写法含义示例
$根节点$
.name / ['name']子节点$.store.book
[n]数组下标，负数表示倒数$.store.book[-1]
[start:end:step]切片，缺省按常规语义补齐，越界截断不报错$.store.book[0:2]
['a','b'] / [0,2]并集$.store.book[0]['title','author']
.* / [*]通配：全部子节点或全部元素$.store.book[*].author
..name / ..[*]递归：任意深度的匹配项（文档顺序）$..author

规范路径口径：点记法优先，如 $.store.book[0].author；含特殊字符的键用 ['...']，数组用 [n]。缺失键会被跳过、只返回实际命中的条目；表达式合法但无匹配时显示「无命中」而非报错。

使用说明

1. 粘贴 JSON 到上方输入框（或点「载入书店示例」）。
2. 在表达式框写以 $ 开头的表达式，或点一组预设填入；JSON 或表达式任一变化即实时重算。
3. 结果逐条含规范路径、类型徽标与值预览；对象／数组值可展开看完整值；点击路径可在下方格式化视图中高亮对应行。
4. 点「复制此条」复制单条命中值（字符串复制原文，其余复制 JSON 文本）；「复制全部结果」复制 [{path, value}] 文本；下载的 jsonpath-result.json 内容与复制全部一致。
5. 复制失败时页面会提示手动复制指引（浏览器未授予剪贴板权限时常见）。

常见问题

为什么表达式合法却显示「无命中」？
说明当前 JSON 里确实没有匹配项：键名拼错、层级少一级或下标越界时都会如此；缺失键会被跳过、不报错，请对照规范路径逐级排查。
过滤表达式为什么报错？
本工具只做常用子集，不支持过滤表达式 [?(...)]、脚本表达式与函数式扩展；遇见时会中文提示不支持并指明位置，不会静默返回空结果。
我的 JSON 会上传吗？
不会。JSON 与表达式全部在浏览器内解析与求值，本页面零网络请求，数据不出本机。

真限制说明

只做常用子集、不承诺完整规范：仅支持上表子集；不支持过滤／脚本表达式与函数式扩展，遇见时中文提示不支持并指明位置。
只做查询命中、不做 Schema 校验与语义对比：不输出实例是否符合 Schema、不对比两份 JSON；要格式化或验证 JSON 去 JSON 解析器，要对比去 JSON 语义化对比器，要校验 Schema 去 JSON Schema 验证器。
命中值原样展示：字符串、数字、布尔、空值、对象、数组均按原值展示，不做类型转换；复制时字符串复制原文、其余复制 JSON 文本。
缺失键跳过、不报错：通配或递归命中时个别对象缺失该键时跳过该分支、只返回实际命中的条目。
零上传：本页面零 fetch／XHR、零 CDN，全部解析与求值在浏览器本地完成，JSON 与表达式不出本机。
