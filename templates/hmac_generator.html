HMAC 生成器

密钥（文本／十六进制／Base64）＋消息文本，浏览器本地算 HMAC-SHA256／384／512：十六进制与 Base64 双输出、带 sha256= 前缀快捷复制、期望签名一致性比对。调 Webhook 与 API 签名时，先在这里把签名算对。

仅调试用，勿贴真实生产密钥。密钥一旦粘贴到任何在线页面（包括本页）即应视为已暴露，事后请轮换。计算全部在当前浏览器本地完成（WebCrypto），不上传到任何服务器、不做任何存储；本页面无后端调用、无外部请求。HMAC 不是加密：签名本身不保密消息，密钥泄露即任何人可伪造签名。

当前密钥口径：文本（UTF-8）；消息文本按 UTF-8 编码。

使用说明

1. 选密钥口径（文本／十六进制／Base64），填密钥与消息，选算法，签名即实时算出。
2. 十六进制密钥须为偶数位、只含 0-9／a-f／A-F；非法输入会中文报错，不输出错误摘要。
3. 把算出的签名或带 sha256= 前缀的版本发给对方验签；收到对方签名后贴到比对区，看一致／不一致结论与归一化对照。
4. 核对时先确认三点一致：密钥口径、算法、消息原文（包括换行与尾部空格）——三者任一不同，签名必然不同。
5. 调 JWT 令牌请去 JWT 签名生成器/验证器（三段式签发／验证）；算文件摘要请去 文件校验和；本工具只做文本消息。

常见问题

为什么对方算出的签名和我算的不一样？先核对密钥口径（文本口令与它的十六进制形式是两组不同字节）、算法（SHA-256／384／512）与消息原文（换行、尾部空格、JSON 空格都会改变签名）。
sha256= 前缀是什么意思？Webhook 验签常见格式，如 GitHub 的 X-Hub-Signature-256；前缀只说明算法，不参与签名计算，比对时会自动剥离。
HMAC 能加密消息吗？不能。HMAC 是消息认证码：证明消息没被改过、且持有密钥的人签过；消息本身仍是明文，保密要靠加密。
十六进制密钥与文本密钥有什么区别？文本密钥按 UTF-8 逐字编码；十六进制密钥按字节解析（两位一位字节）。同一串字符按两种口径算，结果不同。
能算文件的 HMAC 吗？本轮不做文件 HMAC：文件摘要请用文件校验和工具；本工具只做文本消息，避免范围蔓延。

真限制说明

  • 仅调试用，勿贴真实生产密钥：密钥一旦粘贴即视为已暴露，调试结束后请轮换；生产密钥请只在受控的服务端或 CI 密钥库里使用。
  • HMAC 不是加密：签名本身不保密消息，密钥泄露即任何人可伪造签名；需要保密请另做加密。
  • 编码口径：消息文本按 UTF-8 编码；密钥支持文本（UTF-8）／十六进制／Base64 三种口径，结果旁标明当前口径；十六进制须偶数位与合法字符，否则中文报错。
  • 不做文件 HMAC：本工具只做文本消息，不做文件 HMAC；文件摘要已有文件校验和工具。
  • 需安全上下文：WebCrypto 需在 HTTPS 或 localhost 下使用（/tool-web 为 HTTPS，满足条件）；非安全上下文会明确报错，不静默失败。
  • 内容不出浏览器：全部计算在本地完成，零 fetch／XHR、零 CDN，密钥与消息不出浏览器。
