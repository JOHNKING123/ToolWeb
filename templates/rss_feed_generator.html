RSS／Atom 订阅源生成器

频道表单＋条目列表，实时生成 RSS 2.0 / Atom 1.0 订阅源 XML：转义、CDATA、日期换算一次到位

文本不出浏览器：全部生成都在本机完成，本页面不发起任何网络请求、不上传任何输入（零 fetch / XHR），频道与条目内容只留在当前页面。
真限制（请先看清再用）：

1. 只生成静态 XML 文本，不发布、不托管：生成后请自行把 .xml 放到你的网站可公开访问地址，再把该地址提交给订阅平台；本工具不替你发布，也不提供托管地址。

2. 不验证订阅源可达性与链接真实存在：只做 URL 格式提示（缺协议、含空格等），不发请求验活，不承诺订阅器一定收录；链接是否真实存在请自行核对。

3. 日期按浏览器本地时区换算：发布时间（datetime-local）本身无时区，换算结果以浏览器本地时区为准；跨时区发布前请自查时区偏移是否符合预期。

4. 内容不做 HTML 清洗：条目描述／内容原样进 CDATA（内含 ]]> 时分段续写不断串），不消毒、不改写 HTML；粘贴前请自行确认内容可公开。

5. 不做订阅器兼容实测：只按 RSS 2.0／Atom 1.0 规范字面生成，不承诺特定订阅器／播客平台的解析结果，发布前请在目标平台实测一次。

使用说明

  1. 先填频道：标题、链接、描述必填，链接须以 http:// 或 https:// 开头且不含空格；语言默认 zh-CN，可改；版权、管理邮箱、频道图片 URL 可选。
  2. 再填条目：点「添加条目」新增，每条标题与链接必填；描述、作者、分类、发布时间、guid 可选；发布时间空着则不输出日期元素。
  3. 播客音频：enclosure 三件套（音频 URL、长度字节数、MIME 类型如 audio/mpeg）填其一则须填齐，否则会中文提示且不输出。
  4. 转义规则：标题、链接、作者、分类等纯文本字段做 XML 转义（&、<、>、"、'）；描述／内容进 CDATA，内含 ]]> 时分段续写，不截断。
  5. 日期规则：RSS 的 pubDate 用 RFC 822（如 Mon, 26 Oct 2026 07:37:00 +0800）；Atom 的 updated／published 用 RFC 3339（如 2026-10-26T07:37:00+08:00）；均按浏览器本地时区换算。
  6. 格式切换：RSS 2.0 与 Atom 1.0 二选一，切换后输出实时重算；Atom 的 id 默认取频道链接，updated 取最新条目时间或当前时间。
  7. 导出：点「复制 XML」或「下载 .xml 文件」；复制结果与下载内容均与页面输出一致；复制失败时按降级提示手动复制。
  8. 示例：点「博客频道（3 条）」或「播客频道（2 条，带 enclosure）」一键载入，载入后频道、条目、输出三者同步，仍可再改再生成。

常见问题

生成后订阅器就能读到我的频道吗？
不能直接读到。本工具只生成静态 XML 文本，不发布、不托管；你需要把 .xml 放到自己网站的可公开访问地址，再把该地址提交给订阅平台，平台收录情况以平台为准。
链接填错了会怎样？
只做格式提示：缺协议或含空格会中文提示且不输出；但本工具不发请求验活，不验证链接是否真实存在，发布前请自行点开核对。
描述里的 HTML 会被清洗掉吗？
不会。描述／内容原样进 CDATA，不消毒、不改写；内含 ]]> 时分段续写，保证 XML 不破串、内容不截断。
为什么日期有时区偏移？
因为发布时间输入（datetime-local）本身无时区，本工具按浏览器本地时区换算并写出偏移；跨时区发布前请核对偏移是否符合预期。
guid 和链接有什么关系？
guid 空着默认取条目链接，此时 isPermaLink=true；填自定义 guid 则 isPermaLink=false；同一条目换链接后请同步检查 guid 是否仍唯一。
我的频道内容会被上传吗？
不会。全部生成在浏览器本地完成，零网络请求，输入只留在当前页面。
