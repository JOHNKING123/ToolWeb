使用说明

解码：文件经 FileReader 读入 ArrayBuffer 后，用 Web Audio API 的 decodeAudioData 在浏览器本地解码为 AudioBuffer（FLAC/WAV/MP3/OGG/M4A 是否支持取决于浏览器解码器）。
分析：播放链路为 AudioBufferSourceNode → GainNode（音量）→ AnalyserNode（fftSize=2048）→ 扬声器，每帧同时取 1024 点频域数据与 2048 点时域数据；频域值 0–255 归一化为 0..1 的柱高，再做指数平滑（默认 60%）防抖动。
样式：频谱条 —— 96 根柱子从低频到高频排布，颜色按对数频率映射到主题色带；环形频谱 —— 柱子绕圆心放射；波形 —— 时域数据连成的波形线（128 为中线）；圆形波形 —— 时域数据绕成一圈；镜像频谱 —— 柱子上下对称。切换样式即时生效。
主题：霓虹 / 落日 / 海洋三组色带，频率越低取色带越靠前（低频偏冷色）、越高越靠后；波形类样式取主题的首色/第三色描线。
麦克风：getUserMedia({audio:true}) 取流后经 MediaStreamAudioSourceNode 接入同一条分析链，画面随现场声音实时变化；拒绝授权会明确提示原因，文件模式不受影响。
录制：canvas.captureStream(30) 取画面流、MediaStreamDestination 取音频流，两路合成为 MediaRecorder 录制 WebM（优先 vp9/opus，不支持则回落 vp8/opus 或浏览器默认），点「停止并导出」即下载 原文件名-visualizer.webm。
截图：随时点「截取当前帧 PNG」把 canvas 当前画面存为 PNG（原文件名-visualizer.png）。
隐私：全程无网络请求 —— 上传、解码、分析、渲染、录制、下载都在你的浏览器里完成，可在 DevTools Network 面板验证；刷新页面后音频不恢复。

❓ 常见问题

为什么导出视频要等整首歌播完？
因为导出是实时录制：MediaRecorder 录的是正在播放的画面和声音，录多久就产出多久的视频，3 分钟的歌就要录 3 分钟。浏览器没有提供“离线加速渲染频谱视频”的接口，所以无法像音频处理那样几秒算完。
画面不动 / 柱子很矮，是坏了吗？
先看是不是音频本身的问题：静音段、音量很小的段落、频谱很窄的音频（比如纯人声清唱），画面本来就弱。换一首编曲丰富的歌、把音量调大再试；也可以把平滑度调低，画面会更灵敏。
麦克风模式点了没反应？
先看提示文案：拒绝授权会明确告诉你“拒绝了麦克风授权”，需要在浏览器地址栏的权限设置里允许本站使用麦克风后重试；没找到设备会提示“未找到可用的麦克风设备”。麦克风模式与文件模式互不影响。
录出来的 WebM 没有声音？
录制时音频取自播放链路的 MediaStreamDestination：文件模式下必须在播放中录制（暂停时录到的就是静音）；麦克风模式下麦克风须保持接入。导出后用 Chrome / VLC 打开验证，旧版播放器可能不支持 WebM 的 opus 音轨。
导出的文件叫什么名字？
视频自动命名为「原文件名-visualizer.webm」，例如 夜曲-visualizer.webm；截图为「原文件名-visualizer.png」。麦克风模式下以 mic-visualizer.webm 命名。如需其他名字，下载后重命名即可。
