info 原理：为什么服务器看不到你的内容？

1. 压缩：原文先经浏览器原生 CompressionStream（DEFLATE）压缩；
2. 编码：压缩字节做 base64url 编码，拼成 #u1,模式,数据 放在 URL 的 fragment（# 后面）里；
3. 分享：浏览器请求 URL 时不会把 # 后面的内容发给服务器，对方打开链接后由本页 JS 在本地解码、解压、渲染；
4. 加密（可选）：填写口令后，压缩数据经 WebCrypto AES-GCM-256 加密（PBKDF2-SHA256 派生密钥，10 万次迭代，随机盐+随机 IV），密钥只存在于链接 fragment 中，服务端永远不可见。打开时输错口令会明确报错；
5. 零上传：全程零 fetch/XHR，可在开发者工具 Network 面板验证（除页面自身静态资源外无任何请求）。

quiz 常见问题

分享的文本会被上传到服务器吗？
不会。文本只编码在 URL 的 #fragment 里，浏览器发起请求时不会发送 fragment，服务器（包括本站服务器）永远收不到原文。Network 面板可验证：点击生成后无任何网络请求。
口令加密安全吗？忘记口令怎么办？
采用 AES-GCM-256 + PBKDF2-SHA256（10 万次迭代）+ 随机盐/随机 IV，密钥只由你填写的口令在本地派生，绝不上传。忘记口令则无法解密——本站也没有任何办法恢复，请务必通过其他渠道把口令告诉接收方。
链接有多长？太长怎么办？
链接长度 ≈ 压缩后体积 × 4/3。中文文本通常能压到 1/4~1/3。若压缩后仍超过 8KB，页面会给出长度警告：超长链接在微信、短信、二维码等场景可能被截断，建议拆成多段分别分享。
对方打开链接需要安装什么吗？
不需要。任何现代浏览器（Chrome/Edge/Firefox/Safari，含手机浏览器）打开链接即自动解码渲染；加密链接会先提示输入口令。
Markdown 模式支持哪些语法？
支持标题、加粗/斜体/删除线、行内代码与代码围栏、引用、 有序/无序列表、表格、链接、图片、分隔线。渲染前做严格 XSS 过滤，javascript: 等危险协议会被拦截。
链接会过期吗？
不会。数据就在链接本身里，没有服务器存储，也就没有过期一说——但反过来，链接一旦发出就无法撤回，涉密内容请务必加口令。
