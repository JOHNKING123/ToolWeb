User-Agent 解析器

粘贴单条 UA 文本，实时解析浏览器（名＋版本）、操作系统（名＋版本）、设备类型（桌面／手机／平板／机器人·爬虫）、渲染引擎（Blink／WebKit／Gecko／Trident），附原始 UA 回显与一键复制。调接口、看日志、排障时，先把 UA 拆开看清楚。

先说清四项真限制，再用：
  • UA 可伪造，仅供参考：UA 是客户端自报的字符串，任何人都能改写，解析结果不能当作身份或设备证明。
  • Win10 / 11 无法区分：两者都报 Windows NT 10.0，本页一律标为“Windows 10 / 11”，不假装能分清。
  • iOS 引擎一律 WebKit：iOS 强制所有浏览器用 WebKit，Chrome（CriOS）／Firefox（FxiOS）在 iPhone 上引擎也是 WebKit，不是 Blink／Gecko。
  • 不做指纹识别：本页只拆你粘贴的这一串字符，不采集、不推断、不追踪用户身份。

使用说明

1. 粘贴单条 UA（从浏览器开发者工具、服务端日志或 curl -A 里抄来的都行），结果即时出现。
2. 检测顺序是写死的：机器人优先 → Edge 在 Chrome 前 → Opera 在 Chrome 前 → 三星浏览器 → Chrome（含 iOS CriOS）→ Firefox（含 iOS FxiOS）→ Safari → IE → 未知——因为 Edge／Opera 的 UA 里本身就含 Chrome token，不按这个顺序会误判成 Chrome。
3. 无意义输入（如随手打的几个词）各字段显示“未知”，不报错、不猜测；空输入显示空态。
4. 点“填入当前浏览器 UA”可直接看自己浏览器的 UA 拆解；预设载入后可编辑再解析。
5. 想查 URL 参数请去 URL 解析器；想查状态码语义请去 HTTP 状态码参考；本工具只拆 UA 字符串。

常见问题

为什么 Edge 会被认成 Chrome？不会——Edge 的 UA 里确实含 Chrome token，但本页先判 Edg token，所以 Edg 一律判 Edge，不会落到 Chrome 分支；Opera（OPR）同理。
为什么 iPhone 上的 Chrome 引擎是 WebKit 不是 Blink？iOS 强制所有浏览器用系统 WebKit，CriOS 只是 Chrome 的壳，引擎仍是 WebKit；这是系统限制，不是解析错误。
为什么 Windows 只显示“10 / 11”不写死一个？Win10 与 Win11 的 UA 都是 Windows NT 10.0，UA 里没有区分信息，写死任何一个都是编造，所以标“10 / 11”并明说无法区分。
Linux 为什么不显示发行版？多数 Linux UA 只有 Linux token、没有发行版信息；无发行版 token 时本页只写 Linux，不猜 Ubuntu／Debian；UA 里字面带发行版 token（如 Ubuntu）时才显示它。
UA 解析能用来识别用户吗？不能。UA 可伪造、且大量设备 UA 完全相同，本页不做指纹识别、不做身份推断，只做字符串结构拆解。

真限制说明

  • UA 可伪造，仅供参考：UA 是客户端自报字符串，可任意改写；解析结果不能当作身份、设备或访问者证明，风控判断请结合服务端其它信号。
  • Win10 / 11 无法区分：两者 UA 均为 Windows NT 10.0，本页一律标为“Windows 10 / 11”，不假装能分清。
  • iOS 引擎一律 WebKit：iOS 强制所有浏览器使用系统 WebKit；CriOS／FxiOS／EdgiOS 在 iOS 上引擎均为 WebKit，与桌面版不同。
  • 不做指纹识别：本页只拆解你主动粘贴的单条 UA，不采集设备信息、不做跨站追踪、不推断用户身份。
  • Linux 无发行版 token 时不编造发行版：只有 UA 里字面出现发行版 token 才显示，否则只写 Linux。
  • 识别不出给未知，不猜测：无意义输入各字段为“未知”、不报错；空输入为空态，不输出占位结论。
  • 内容不出浏览器：全部解析在本地完成，零 fetch／XHR、零 CDN，粘贴的 UA 不上传到任何服务器。
