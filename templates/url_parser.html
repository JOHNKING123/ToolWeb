安全提示区（请先看清再用）：

1. @ 之前不是真正主机：含用户名/密码的链接里，@ 之前只是用户信息，真正主机在 @ 之后，谨防钓鱼链接把假主机写在 @ 前面。

2. 默认端口消隐：http 的 80 端口与 https 的 443 端口是默认端口，解析时标注为「默认端口」，重组时消隐不写出。

3. 查询值中 + 在表单语义下表示空格：参数表按表单语义解码 + 为空格，重组时空格写成 %20，语义不变。

4. 本工具不验证链接可达性、不展开短链：只解析字符串本身，不发请求验证链接是否能打开，短链的目标地址不会被展开。

5. 含密码链接勿外传：密码段默认掩码显示，含密码的链接不要截图外发、不要粘进聊天记录。

6. 相对 URL 补协议头：无协议输入默认按 https:// 补齐并在结果区明示，不静默改写你的输入。

menu_book 使用说明

  1. 粘贴长链接点「解析链接」：八段拆解区按浏览器 URL 原语展示协议、用户名、密码、主机、端口、路径、查询、片段。
  2. 密码默认掩码：点「显示明文」可切换查看，含密码的链接不要截图外发。
  3. 在参数表里直接改键与值：重复键分行保留不合并，空值（key=）与无值（只有 key）用类型徽标区分，勾选「有等号」可切换两者。
  4. 点「新增参数」加一行、点「删除」去掉一行，改表后重组预览实时更新，点「重组链接」确认最终结果。
  5. 点「复制链接」或「复制 JSON」导出：JSON 含八段、参数数组、原始输入与是否补齐协议标记。
  6. 点示例一键载入 4 组典型链接（请按需改写），载入后仍可编辑再重组；点「重置回初始输入」回到本次解析的原始输入。

quiz 常见问题

为什么 @ 前面的主机不能信？
因为 @ 之前只是用户信息：https://bank.example.com@evil.example.com/ 的真正主机是 @ 之后的 evil.example.com，@ 前的 bank.example.com 只是用户名，最容易被钓鱼链接利用。
无协议输入会怎么处理？
默认按 https:// 补齐，并在结果区明示「已自动补齐 https://」，不静默改写；// 开头的协议相对链接补 https:。
默认端口为什么重组后不见了？
http 的 80 与 https 的 443 是默认端口，浏览器本身也会消隐它们；解析时标注为「默认端口」，重组时按规范省略，非默认端口（如 8443）会保留。
空值和无值有什么区别？
coupon= 是空值（有等号、值为空），promo 是无值（连等号都没有）；有些后端对两者处理不同，所以参数表把两者分行、分类型保留，重组时也原样区分。
为什么 + 会变成空格？
查询串按表单语义解析：+ 表示空格；重组时空格写成 %20，与 + 的语义相同，再解析回来的参数值不变。
我的链接会被上传或验证吗？
不会。全部解析在浏览器本地完成，零网络请求；不验证链接是否可达，也不展开短链。
