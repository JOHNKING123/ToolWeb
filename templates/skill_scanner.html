info
真限制请先看清：① 本工具是静态规则扫描，不是沙箱执行 —— 检出的是「风险特征」不是确诊，没检出也不代表绝对安全；② 加密/混淆脚本的检出率有限，高度混淆的载荷可能漏报，可疑来源的 SKILL 建议直接弃用；③ ZIP 包请逐个粘贴：一个 SKILL 包多个 .md 文件时，请逐个粘贴（或逐个上传）扫描，本工具一次处理一份文本；④ 扫描纯本地进行，SKILL 文本不出浏览器（可在 Network 面板自证），建议用可疑文本直接粘贴扫描，不要先传网盘。

input 粘贴 SKILL.md 文本或上传 .md 文件（输入即实时扫描）

文件通过浏览器 FileReader 在本地读取，不上传到服务器。frontmatter 指文首 --- 包裹的「键: 值」声明块（name/description 必填）；正文逐行做静态正则扫描：curl/wget 外发执行、base64 解码执行、反向 shell、rm -rf 等破坏性命令、密钥硬编码、环境变量读取、提示词注入话术。

assessment 扫描报告

安全评分口径：高危每条扣 25 分、中危每条扣 10 分、低危每条扣 3 分，下限 0 分；≥80 分为「安全」、≥50 分为「警告」、低于 50 分为「危险」。评分只反映静态规则覆盖范围内的风险密度，不是安全承诺。
LLM 安全一条龙：① 先用本工具 扫 SKILL 包（防恶意脚本/提示词注入）；② 喂 LLM 前去 .env 脱敏生成器 把自己的密钥脱敏；③ 再去 代码打包给 LLM 把项目打包成单个 TXT —— 扫描、脱敏、打包三步走，安全地喂 LLM。

help_outline 常见问题

扫描没报风险，是不是就可以放心安装？
不是。本工具是静态规则扫描，只能检出已知风险特征；加密/混淆过的脚本、规则库之外的手法都可能漏报。来源可疑的 SKILL 包，最稳妥的做法是直接弃用，而不是依赖扫描结论。
报了高危就一定是恶意 SKILL 吗？
不一定。检出的是「风险特征」：比如运维类 SKILL 可能正当使用 curl 下载官方脚本。请结合行号定位看上下文，按修复建议人工确认后再决定用不用。
为什么一次只能扫一份文本？
ZIP 包里多个 .md 文件请逐个粘贴或逐个上传扫描 —— 风险项带行号定位，混在一起反而对不上行。每个文件单独出一份报告最清楚。
文本会上传到服务器吗？
不会。本工具纯前端运行，解析、扫描、评分、复制全在浏览器本地 JavaScript 里完成（文件上传走 FileReader 本地读取），脚本中没有任何 fetch / XHR 上传逻辑。可断网使用（首次加载页面除外）。
frontmatter 的 name 有什么讲究？
name 是 SKILL 的唯一标识，Agent 靠它识别调用。规范是小写字母/数字开头，只含小写字母、数字、下划线、连字符；description 必填，写清这个 SKILL 是干什么的，Agent 靠它决定何时调用。
