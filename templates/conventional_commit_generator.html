Conventional Commit 提交信息生成器

选 type、填 scope 与描述，实时生成规范提交信息：一键复制或下载 commit-message.txt，纯前端不上传

本工具只生成单条提交信息，不做 git 操作：不执行 commit、不读写仓库、不校验分支与历史；不校验团队约定：不检查 issue 号格式、不强制 scope 白名单、不做提交历史 lint；不做翻译与润色：描述按你的原意输出（仅去首尾空格），不改写措辞；breaking 只按 Conventional Commits 标准表达：标题 ! 加 BREAKING CHANGE: footer，不扩展自定义 footer 体系。

填写提交信息

新功能：向用户交付的新特性

scope 只允许小写字母、数字、连字符（-）和下划线（_）；含空格、大写字母或中文时会有中文提示且不输出误导性结果。

描述为空时会有中文提示且不输出；超过 72 字符时仅提示「建议精简」，仍正常生成，不阻塞。

正文里的换行会统一转为空格（提交信息单段表达），不保留多行结构。

breaking 开启但说明为空时，标题只加 !，不生成空 footer，并提示建议填写破坏性说明；说明里的换行同样转为空格。

输入变化时提交信息实时重生成；示例载入后仍可再改再生成；「恢复默认」回到 feat、无 scope、空描述／正文／breaking、breaking 关闭。

生成的提交信息

暂无可复制的提交信息：请先按提示修正输入。

复制与下载的内容与上方输出框完全一致；复制失败时会提示手动全选复制的降级办法。

使用说明

  1. 先选 type：11 项（feat／fix／docs／style／refactor／perf／test／build／ci／chore／revert），默认 feat，每项下拉下方有中文适用说明。
  2. 再填 scope（可选）：留空则标题不带括号，如 feat: 描述；填 api 则为 feat(api): 描述；只允许小写字母、数字、连字符、下划线。
  3. 描述必填：单行写本次提交做了什么；为空时中文提示且不输出；超 72 字符仅提示建议精简，仍生成。
  4. 正文可选：多行文本框，换行统一转为空格；有正文时标题与正文之间空一行。
  5. breaking 开关：开启后标题 type／scope 后加 !，如 feat(api)!: 描述；有说明时再空一行追加 BREAKING CHANGE: 说明 footer，无说明时不生成空 footer。
  6. 复制与下载：一键复制把提交信息放进剪贴板；一键下载保存为 commit-message.txt；两者内容与输出框一致。
  7. 示例与恢复：点三组示例一键载入（feat 含 scope＋breaking、fix 无 scope、docs 无 scope），载入后仍可再改；「恢复默认」回到初始值。
  8. 互链：要生成 .gitignore 去忽略文件生成器；本工具只生成提交信息文本，不生成忽略文件。

常见问题

标题格式到底是怎样的？
无 scope：type: 描述；有 scope：type(scope): 描述；breaking 开启：type(scope)!: 描述。scope 留空时不出现空括号。
breaking 的 ! 和 BREAKING CHANGE 有什么区别？
两者是同一破坏性变更的两种标准表达：标题加 ! 是简写，有说明时再追加 BREAKING CHANGE: 说明 footer 写清影响；说明为空时只加 !，不生成空 footer。
描述为空或 scope 非法时为什么没有输出？
这是有意的：空描述或非法 scope 生成的结果会误导复制粘贴，所以输出区置空并中文提示是哪一项错，改对后立刻重新生成。
描述超过 72 字符会被拦住吗？
不会。只提示「建议精简」，仍正常生成；72 字符是 Conventional Commits 常见的标题长度建议，不是硬上限。
正文里的换行去哪了？
转为空格了：本工具只生成单条提交信息，正文与破坏性说明按单段表达，不保留多行结构。
点复制后能直接 git commit 吗？
能粘贴使用，但本工具本身不做 git 操作：不执行 commit、不读写仓库、不校验分支与历史，粘贴后的提交由你自己在终端执行。
我的输入会被上传吗？
不会。全部在浏览器内生成，零网络请求，零 CDN，本页 JS 源码无任何 fetch／XHR 调用。
