menu_book 使用说明

  1. 打开你的 MCP 客户端配置文件：Claude Desktop（claude_desktop_config.json）、Cursor（.cursor/mcp.json 或设置页）、OpenCode（opencode.json 的 mcp 段，注意其顶层键名与客户端有关）。
  2. 复制其中的 mcpServers 配置 JSON，粘贴到左侧文本框（或直接上传 .json 文件），报告实时生成。
  3. 按严重程度阅读：错误必须修（配置无法加载），警告建议修（运行时大概率出问题），建议按需优化。
  4. 每条诊断都给出定位与修复建议；一键复制报告可把文本版报告粘给 AI 或同事协助排查。
  5. 配置合法时会显示全绿通过。注意：本工具只做静态诊断，不会实际启动 server 进程（浏览器里做不到）。

help_outline 常见问题

为什么说顶层键名拼写是 #1 常见 bug？
大量 MCP 配置"静默失败"（配了但一个 server 都不加载）的根因是顶层写成了 mcp_servers、MCP_SERVERS 等。客户端只认大小写敏感的 mcpServers，拼错不会报错、只会静默忽略。本工具会把它标为错误并给出正确写法。
JSON 语法错误能定位到行列吗？
能。解析失败时会报出"第 X 行，第 Y 列"并展示该行内容，常见元凶是多余的尾逗号、未闭合的引号/括号。修好语法后可先用 JSON 解析器格式化确认。
stdio / http / SSE 三种 server 都支持吗？
支持。默认按 stdio 检查（必须有 command）；检测到 url 或 type 为 http/sse 时按远程型检查（必须有 url）。建议给远程型显式声明 type，避免客户端按默认 stdio 解析。
npx 缺包名是什么意思？
"command": "npx", "args": ["-y"] 这样的写法漏了包名，npx 不知道要运行哪个包。正确写法如 "args": ["-y", "@modelcontextprotocol/server-filesystem"]。
${VAR} 引用的环境变量怎么检查？
工具会扫描 command / args / env 值里的 ${VAR} 形式引用；凡在同级 env 里没定义的都会告警——运行时它可能展开为空导致 server 启动失败。确认变量来自系统环境的可忽略。
同名重复条目为什么危险？
JSON 里同名键只保留最后一个，前面的被静默丢弃。你会看到"明明改了配置却没生效"。本工具扫描原文（而非解析后的对象）来发现重复定义。
我的配置（含 API Key）会上传吗？
不会。解析、诊断、报告渲染、复制全部在浏览器本地 JavaScript 里完成，脚本中没有任何 fetch / XHR 上传逻辑，断网可用（首次加载页面除外）。
