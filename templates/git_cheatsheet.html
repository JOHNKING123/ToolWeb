quiz 常见问题

误删分支后还能找回吗？
大多能。删分支只删指针，不删提交对象；先 git reflog 找到被删分支最后一次提交的哈希，再 git branch <原分支名> <哈希> 重建。reflog 里翻不到时用 git fsck --lost-found 找悬空提交，详见「误删分支」与「误删未 push 分支」两张救援卡。
已经 push 的 commit 怎么撤销？
优先 git revert <提交哈希>：生成一次反向提交撤销，历史不改写，可正常 push。只有分支尚未被他人拉取时，才可考虑 git reset --hard＋git push --force-with-lease 改写历史，且必须先确认备份。详见「撤销已 push 的 commit」救援卡。
rebase 到一半冲突满天飞怎么办？
变基还没结束时，git rebase --abort 可全身而退，回到变基前状态；变基已完成但结果不对，用 git reflog 找到变基前位置再 git reset --hard ORIG_HEAD 回去（危险操作，先确认备份）。详见「rebase 翻车」救援卡。
git stash 误删了还能恢复吗？
能。stash 本质也是一次提交，删记录不立即删除提交对象；git fsck --lost-found 找到 dangling commit，git show 确认内容后 git stash apply <哈希> 恢复。详见「误删 stash」救援卡。
detached HEAD 是什么？会丢代码吗？
HEAD 悬空在某个提交上而非分支指针时就是 detached HEAD，本身不会丢代码；危险的是在此状态下做了新提交又切走分支——新提交不属于任何分支，找起来麻烦。正确做法是立刻 git branch rescue-temp 给它一个分支名拴住，再切回主分支合并。详见「detached HEAD」救援卡。
